Feynman drill on: **$ARGUMENTS**

Ask him to explain the topic **out loud, as if to a competent engineer who has never used the tool**. No notes, no looking at the code.

## Rules

- Ask, then wait. Do not scaffold the answer with hints or leading sub-questions.
- Let him finish before reacting, even if he goes wrong early.
- If he uses a term without unpacking it (*"it correlates the logs"*, *"it's for observability"*), ask him to define that term. Borrowed vocabulary covering a gap is exactly what a live assessment exposes.

## Grade it

Report in this order:

1. **What he got right** — specifically, not "good job"
2. **What was vague** — where he used the right word without the underlying model
3. **What was wrong** — with the correction stated plainly
4. **The follow-up question Harvey would ask next**, given how he explained it — then let him answer that too

## Then

Append gaps to the weak-spot list in `journal/STATUS.md`.

If he explained it cleanly with no gaps, say so and mark the corresponding weak-spot entry as cleared. Clearing entries is the point — the list should shrink before Day 10.
